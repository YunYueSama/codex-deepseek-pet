# 正常速度动画检查

2026-09-16，检查 preview.2 当前工作区。结论：动作连续性不合格，不能凭 32 张图或接近 60 FPS 宣称流畅。

## 方法与证据

运行 `node scripts/realtime-motion-qa.cjs`，使用实际 Electron 的 draw/paint，以真实时间 1 倍速连续播放待机、重心调整、走路、挥手、进食、跳跃、入睡、哼歌、摇尾巴九组。录制未手动逐帧推进；保存 WebM、每约 100 ms 的时间序列截图和原画切换时间。视觉判断依据这些实际播放采样，不能等同于人类连续观看全部视频。

测试固定动作，排除随机事件插入；使用独立测试配置，不修改用户设置。输出位于 `artifacts/realtime-motion-qa/`，`index.html` 可逐项播放原速录制。此测试只检查身体动画，不验证角色在桌面的移动速度与脚步是否完全同步。

## 复现的问题

| 动作 | 正常时长内观察到的问题 | 对应实现原因 |
| --- | --- | --- |
| 重心调整 | 一张姿势停留约 100–200 ms，切换时发型、脸和裙子轮廓一起跳 | 补绘采用两个批次交错，且原画密度仍低 |
| 走路 | 转身接步态时造型变化；一组相似跨步后突然变成收腿，循环重复 | gait 将相似姿势按四张成组，缺少准确的连续支撑、经过和伸腿中间态 |
| 挥手、进食 | 手动作以外，头身比例与尾巴轮廓也交替变化 | 编译按整身高度对齐，不能修正不同画稿内部比例差异 |
| 跳跃 | 约一秒内切换多个不连贯的蹲、腾空、伸手和收腿姿势 | 画面顺序改变后仍沿用旧时长数组；位置曲线也沿用旧的腾空区间 |
| 入睡 | 后段已闭眼趴下，又切回睁眼、尾巴抬起的姿势 | sleeping 顺序先播放至 30，再回到 19/21 等早期姿势 |
| 哼歌 | 眼睛、面部与身体轮廓切换感明显，收尾跳回另一张站姿 | 两批画稿的中间帧并非严格前后相邻的同一造型 |
| 摇尾巴 | 尾巴变化是若干轮廓切换，身体也有细微跳变 | 完整原画之间缺少稳定的根部和连续弧线，60 FPS 绘制不会补齐形态 |

## 性能的解释范围

录制时走路约 56.5 FPS、P95 17.6 ms；摇尾巴约 60 FPS、P95 16.8 ms；存在 55–123 ms 的个别长帧。MediaRecorder 和截图均有额外开销，不能据此将长帧全部归因于实际桌宠，更不能把平均 FPS 当作动画质量证明。

## 修复顺序

先停止将不同批次画稿机械交错。以一个稳定角色模型的接触、下沉、经过、抬升姿势重做步态和循环接缝；按每个姿势的实际运动阶段制定时长，再同步移动速度。入睡剔除倒退姿势，跳跃重建准备、腾空、落地的统一时间线。尾巴与身体按同一动作阶段设计，单独验收根部、弧线和收尾连续性。每组都需正常速度前后对照通过后才接入 EXE。
