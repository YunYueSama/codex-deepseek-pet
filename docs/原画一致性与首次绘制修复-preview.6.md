# 原画一致性与首次绘制修复 · preview.6

修复了首次切换动作时处理大图集造成的停顿，并替换闭眼安定阶段的 6 张原画。

## 首次绘制

此前运行时从整张图集中裁切绘制。无录制测试发现，第一次进入某些动作时，`drawImage` 调用会耗时约 40–80 毫秒，随后绘制则很快。

现在启动时预裁实际会播放的 253 张完整角色 `ImageBitmap`，运行时只绘制单帧。预处理完成后释放源 `HTMLImageElement` 与大画布，保留尺寸信息、命中位图和单帧纹理。没有改变透明命中、缩放或单层绘制方式，也没有用交叉淡化掩盖姿势差异。

同机、14 个动作、每个约 2 秒、无视频编码和截图的对比：

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 超过 33.4 ms 的 rAF 回调间隔 | 11 次 | 0 次 |
| 最大 rAF 间隔 | 77.8 ms | 11.2 ms |
| 最大单次 paint CPU 耗时 | 78.9 ms | 0.3 ms |

测试屏幕的回调频率约 180 Hz，应用绘制目标仍为 60 FPS；两者不能混称。正常动态动作实测绘制约 60 FPS。起步转身中的相同姿势会跳过重复绘制，因此不能把相邻 paint 调用的间隔直接当作卡顿。上述是本机短时测试，没有作跨硬件或长期零长帧保证。

## 原画

闭眼安定阶段的 21、23、25、27、29、31 帧重新绘制为同一组连续姿势：维持头部、躯体与脚底位置，尾巴轻微收拢，发梢随之安定。入睡和起身共用这组画面。没有调整其他动作的帧数。

![重新绘制并接入的六张安定姿势](sleep-rest-preview.png)

原图、参考图和完整提示词保存在 `design/sources/sleep-rest-v1/`。生成工具仍把棋盘格画进了背景；根据此前授权，本地清除了与边缘连通的中性背景，并统一整张角色的尺寸与落脚位置，没有拆分肢体。
