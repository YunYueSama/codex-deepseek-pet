三个剧情单项冷却 10 分钟，剧情之间间隔 3–5 分钟；点击会从当前画面收尾，最长 1.8 秒。专注、安静、全屏、聊天、离开和拖拽时不自动触发剧情。正常待机 3–5 秒后选择小动作，短表演另有冷却和环境权重，避开最近三种动作。

原有吃东西、挥手、跳跃、跳舞、入睡各补至 32 张；偷吃剔除道具冲突后使用 22 张；走路更换为 32 张新绘步态，增加缩步与双脚经过身体下方的阶段。转身仍使用原有 8 张，部分情绪仍为关键姿势切换，尚未全部补为连续原画。画稿与生成提示分别保存在 `design/sources/stories-v1` 和 `design/sources/dense-v1`。

## 角色方向

她陪你一起忙，有时认真得皱眉，有时偷偷给自己找点乐子。可爱来自有原因的小反应：想不出来会换个姿势，摸鱼被发现会收敛，完成任务后才得意。避免不断向用户表演、每次思考都吃东西，或者用撒娇打断工作。

外观继续遵循 `design/character-standard.png`，动作使用完整角色逐帧绘制。四张新社区图提供招呼、嘴硬、得意和张臂的表情参考，不直接拼接成动画。

## 建议优先绘制的动作

### 三张补充图带来的小剧情修订

用户新增的 [工作小剧情参考](../design/references/community-20260916/README.md) 为“工作时唱歌”“等测试去吃饭”“偷吃 token 玩 Wordle 被抓包”提供了直接图片依据。原始发布来源仍未核实；Qwen 翻译梗仍未获得对应图片或原始出处。以下是基于画面的桌宠改编，不是已实现功能。

1. **工作念叨变成歌**：先看向工作侧、轻轻点头 → 嘴里念叨 → 节奏渐起、肩膀轻摆 → 闭眼笑、双手收在胸前。被点击时短暂停顿，再睁眼收手：“没跑题，我就是……带点节奏。”声音默认关闭；专注模式不随机播放这个小剧情。原画预算 40–48 帧，另绘 16–24 帧被发现分支，不能突然切成立正姿态。
2. **等测试，先惦记饭**：仅在已接入的任务事件确认测试开始后，看看进度 → 摸摸肚子 → 指一下工作侧 → 拿起食物侧身走两步。台词可用“测完叫我，我就吃一口。”收到结果时先放下食物再转身回来；失败时认真查看，不庆祝。未接入测试事件时只作为用户主动点播的小剧场，不声称知道测试进度。原画预算 40–48 帧，返回另绘 24–32 帧。
3. **偷吃后摸鱼被抓包**：休闲时托腮 → 看向 token → 犹豫后拿一颗 → 拿出小字谜板投入玩耍 → 点击时双手停住、惊讶、藏起板子 → 嘴硬收尾。可说“这、这是……脑力热身！”保留漫画的辩解神态，但不向用户谎报真实“性能测试”。玩字谜首先是道具动画，不自动启动程序或消耗 API；若后续开放真实小游戏，由用户主动进入。原画预算 64–80 帧，另绘 16–24 帧打断分支。

三种剧情共用“准备—投入—恢复”的组织方式，但分别绘制身体与道具衔接。事件在中途结束时尽快自然收尾，不为了播完整段拖延聊天结果。长剧情沿用下文冷却规则，不因为有多个分段而重复计算触发次数。

| 动作 | 完整表演过程 | 情境与小台词 | 原画预算 |
| --- | --- | --- | --- |
| 托腮想题 | 身体转向工作侧 → 手掌托腮、另一手支住肘部 → 眉毛轻收 → 放手坐正 | 聊天请求等待中；默认无台词 | 24–32 帧，4–6 秒 |
| 掰指头验算 | 看向自己的手 → 依次轻点手指 → 停一下重新数 → 小幅点头 | 请求等待时的低频变体，不声称揭示模型真实思维过程 | 32 帧，5–7 秒 |
| 借 Qwen 字典 | 翻小册子 → 皱眉 → 侧身搬来写着 Qwen 的小册子 → 对照阅读 → 合书 | 用户主动开启翻译时；“我查一下，这叫严谨。” | 40–48 帧，6–8 秒 |
| 偷偷哼歌 | 看向一旁 → 闭眼轻晃肩膀、尾巴跟拍 → 哼两小节 → 收回姿态 | 休闲且允许声音时；默认只做无声口型与音符表现 | 32–40 帧，5–7 秒 |
| 哼歌被发现 | 接续哼歌姿态 → 顿半拍 → 收起手与肩膀 → 假装认真 → 偷笑 | 仅在哼歌过程中被用户点击；“咳，我在整理思路。” | 16–24 帧，2–3 秒 |
| 藏一颗 token | 看向小口粮 → 手伸到身侧 → 拿一颗 → 咬下 → 擦嘴、装没事 | 休闲彩蛋；“这是脑力补给。”不显示虚构账户扣费 | 32–40 帧，5–6 秒 |
| 想通后忍笑 | 停下当前思考 → 眼睛亮起 → 身体稍向前 → 小幅握拳 → 得意收回 | 仅任务成功或回答结束时，失败不得庆祝 | 24 帧，3–4 秒 |
| 等待时晃脚 | 坐稳 → 双脚交替小幅摆动 → 尾巴缓慢跟随 → 脚收回再起身 | 已稳定坐在承托边缘、确有等待状态；不在悬空或移动支撑上播放 | 24–32 帧，4–6 秒 |
| 揉眼伸懒腰 | 放下道具 → 短暂揉眼 → 肩背伸展 → 呼气放松 | 一段专注结束后；“歇半分钟？”只提示一次 | 32–40 帧，5–7 秒 |
| 偷看工作进度 | 身体转向工作侧 → 轻轻探头 → 看一眼 → 安静缩回 | 有已授权的宿主任务状态时；不恢复鼠标注视功能 | 24 帧，3–4 秒 |

上述为绘制预算，不是已经完成的帧数。原画需按动作节奏调整，停顿允许持帧；屏幕渲染仍以 60 FPS 为目标，不用叠影补帧。优先制作托腮、借字典、哼歌及被发现、想通忍笑这五组，形成可衔接的小剧情。

## Qwen 梗如何落地

先用“借字典”表现她认真求助又爱面子的性格。动画播放不下载模型、不联网、不改变用户文件。如果以后加入真实本地翻译功能，须由用户选择模型并启动下载，界面显示真实大小、进度与结果；取消或失败就收起册子，不演出下载成功。不能为播放彩蛋真实消耗下载流量或 token。

## 频率与打断规则

以下是待验证的初始调参值，不能直接当作验收结论：

- 工作模式只允许轻微安静动作，每 45–90 秒最多一次；休闲模式每 25–50 秒评估一次候选，允许不播放，避免固定节拍。
- 长小剧情间隔至少 3–5 分钟；同一小剧情至少 10 分钟不重复，最近三种表演降低权重。思考姿态可保持，但不能循环掰手指或连续假装顿悟。
- 一次请求最多选择一个思考主动作。结果到来时，从当前姿势自然收回，再进入反馈；中途失败用平静恢复，不先庆祝再报错。
- 用户拖拽、聊天和主动操作优先。被点击的反应必须接续当前身体姿态，道具在手里时先放好；禁止突然换回正面站姿。
- 专注、会议、全屏和静音场景不主动唱歌；实际音频默认关闭，后续采用原创短哼唱。没有可靠会议检测时，以用户的安静模式为准。
- 环境动作只使用已接入且获准读取的状态。没有窗口内容识别能力时，不能声称“看懂了你的代码”；不为随机动作持续截屏或调用模型。

## 动画验收重点

完整角色姿态包括肩、胸廓、骨盆和脚的重心变化；托腮时手与脸稳定接触，手肘支撑清楚。哼歌不能只有头在晃，腿也不能随肩膀摆动而变短。尾巴有轻微延迟，但保持一条且连接点稳定。

逐组检查准备、表演、恢复和被打断的画面；再测试快速回复、请求失败、重复点击、拖拽、支撑窗口移动或消失、安静模式与不同缩放比例。确保新动作不产生滑脚、穿窗、道具闪现、残影或高频打扰后，再打包发布。
